# ADR-0012 — Bounded rendition pyramid and worker transport

Date: 2026-10-29. Status: accepted for the owner's next-stage request, continuing P2. Preserve originals, catalog identity/schema, dependency locks, existing retained-version gates and P0/P1 evidence. P3 resource scheduling and preservation operations remain separate.

Extend the existing 32/256/512 px preview tiers with 1024 px gallery and 2048 px viewer renditions. Select gallery tiers from rendered dimensions and device pixel ratio under an explicit decoded-pixel admission estimate; reserve the largest tier for the explicitly opened viewer. Retain smaller usable renditions while larger images load or fail. These are disposable SDR previews, not original-resolution viewing or full-media verification. Keep the existing cache byte cap and decoder concurrency/input/dimension/time/RSS limits.

Use a versioned worker frame: fixed magic/version, bounded JSON metadata header and raw PNG body. The existing numeric-array JSON response adds avoidable transport/allocation cost and becomes particularly expensive for larger PNGs. Validate the frame, exact lengths, requested tier and independent PNG header dimensions before cache publication. Bound header and body separately. Keep legacy diagnostic modes available; unknown modes continue to fail before application startup. The renderer still receives typed IDs/statuses and reads a scoped, read-only cache protocol, never original paths or worker framing.

Avoid a dependency, decoder, schema migration, global scheduler or default cache expansion. Existing positive previews remain compatible; pipeline-versioned failures can retry under the new policy. Exact local platform evidence and unavailable release gates belong in PERFORMANCE_P2.md; no existing P0/P1 measurements establish this stage's results.

Measured hot paths justify two small changes within P2. Resolve up to64 preview keys with one indexed cache lookup/touch and one narrow status projection, rather than issuing catalog actor calls per tier/policy/key. No schema migration or filesystem I/O enters the actor. Prioritise visible rows before overscan for rendition admission; selection and DOM order remain chronological. Keep the existing justified-row solver and its64-item search bound, but stop considering multi-image rows below half the requested height. A single panorama may naturally be shorter. This prevents dense synthetic days collapsing into near-invisible strips without replacing the layout algorithm.
