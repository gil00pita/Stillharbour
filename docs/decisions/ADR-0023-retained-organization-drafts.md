# ADR-0023 — retained organization drafts and template versions

Date: 2026-10-31. Status: accepted for the owner's request to finish M2; M2 acceptance remains open.

The next prerequisite after ADR-0022 is durable planning. Use catalog schema 3, with immutable template versions and immutable draft content, rather than an unrelated draft file or renderer persistence. Existing catalogs first receive an independently openable, integrity/FK/UUID-checked SQLite Backup snapshot. A failed snapshot prevents migration. Migration creates tables/triggers and advances the schema inside one transaction; catalog UUIDs, roots, native locators and existing history are retained. Older applications must use their retained pre-migration copy rather than opening schema 3 or downgrading it in place.

On Windows local NTFS, publish only the application-created snapshot using a held directory chain, source identity/link checks, native directory-relative `NtSetInformationFile(FileRenameInformation)` with replacement disabled, and file flushing before and after publication. Reopen the published identity and independently read the SQLite file. The leaf directory permits write sharing for the internal rename open; no directory permits delete sharing. Ordinary scanner handles keep their existing stricter sharing. Failed publication retains its stage. This adapter does not implement generic original-file publication or directory fsync. [Microsoft's file caching documentation](https://learn.microsoft.com/en-us/windows/win32/fileio/file-caching) describes flushing file data and metadata; [the native information API](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/nf-ntifs-ntsetinformationfile) defines the rename call. Process-exit fixtures are not hardware/power-loss proof or evidence for remote/other filesystems.

Schema 3 adds append-only organization_templates, organization_plans and operation_journal. Saving a template appends a version using compare-and-swap against the last version. Bound history to 100 templates, 100 versions each, 1,000 drafts and 240 selected photos per draft. Templates retain the supported token/policy metadata; editable policy selection and representative sample inputs/outputs remain unfinished. A single transaction inserts a draft and its journal event after checking the current catalog revision and any selected immutable template version.

The draft fingerprint includes its catalog UUID, private native source observations, destination native locator/identity/volume, resolved preview, template reference, policy and creation identity. Verify the fingerprint, schema policy, catalog binding and bounded payload when loading. Database triggers prevent ordinary content/history rewriting; the hash detects accidental damage, not hostile database forgery. Neither a trigger nor a digest grants filesystem authority. Reopening checks current catalog observations for staleness but does not revalidate or reserve the destination. Original native paths stay in Rust and are omitted from JSON/CSV review exports.

Separate pure DTO/validation/export rules in operations.rs from SQL in library/operation_store.rs, shared native directory handling in filesystem/directory.rs and the scoped snapshot adapter. Tauri resolves picker-session authority; the renderer supplies only typed settings, IDs and the preview fingerprint. The UI saves drafts explicitly, loads retained history without a current selection and displays frozen paths, staleness, blockers and JSON/CSV text. CSV cells are quoted and formula-prefixed; JSON preserves exact display text. Native file-save export and before/after trees remain unfinished. Errors never become empty successful history or an executed operation.

Only draft state is admitted by the current loader. All drafts retain four blockers: native target checks, complete companions, capacity/fidelity and execution/recovery. No approve/start/import/undo command exists. Future execution must add validated native preconditions, review/approval binding, state transitions and the centrally locked executor; it must not reinterpret this draft as executable. All P4, native and independent recovery requirements remain in force.

Architecture assessment: 8/10 for this bounded planning slice. Business rendering/export rules remain independent of SQL/Tauri and native handles stay in adapters. Remaining improvements are explicit validated policy types/sample fixtures, separate executable-plan validation/state transitions and fault-tested executor ports. This score is a design assessment, not preservation evidence or M2 completion.

Validation uses generated temporary media/catalogs only: snapshot late-collision/wrong-identity rejection; independent WAL snapshot reads; migration rollback and process exits after snapshot/before commit/after commit; template CAS/history retention; plan immutability, catalog/digest binding, reopen/staleness and safe export; component and native review flows. Actual command outcomes belong in the implementation log. macOS, physical unplug/disk-full, power loss, original execution/import/undo and M4 exact-version recovery are not established by these fixtures.
