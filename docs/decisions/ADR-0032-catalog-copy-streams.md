# ADR-0032 — Catalog-backed copy streams and schema-4 journal indexes

Date: 2026-10-31. Status: catalog-adapter development under disposable fixture capability; production copying remains unavailable.

## Catalog migration

Schema 4 adds operation_journal_scope(plan_id, phase, item_id, sequence) and a unique partial operation_copy_stream index on (plan_id, item_id) for copy_execution_plan_v1 records. No existing record, catalog UUID, root identity, application identifier or extension changes. Keep the previous consistent catalog snapshot before migrating any existing version. Create both indexes and advance the schema in the existing transaction; any collision/failure rolls everything back. Do not silently accept an unexpected same-name index/table, drop history or downgrade a live catalog. New catalogs create the complete schema directly through the existing migration path.

The native migration fixtures now exit after snapshot, before commit and after commit from both schema 2 and schema 3. Schema-3 tests independently open retained snapshots, verify UUID/history and test a collision at the second index, proving the first index rolls back too. These are process-exit/database-consistency results, not physical power-loss proof. No real user catalog is opened as a test.

## Copy journal adapter

Give the central engine a small CopyJournal interface; keep its existing owned SQLite adapter and add a catalog-actor implementation. The latter binds an immutable stream to a validated retained draft and compiled companion manifest, the current catalog UUID, managed source-root grant, exact native source identities/revisions/sizes, destination identity/volume and exact source/target/stage mapping. Current adapter scope is one source root with direct source files and flat output names. Different/nested scopes fail closed. The engine and constructors remain compiled only for tests/fixture-probes; this is not a renderer path interface or production approval service.

Retain at most 64 KiB per stream binding and 8 KiB per event. SQL bounds evidence bytes before returning retained payloads to Rust. Stream events have explicit ordinals/digests and exactly six ordered file phases: intent, stage created, flushed, verified, publication intent and completed verified. Validate evidence against the immutable plan, expected stage volume/object, byte counts and verified digests/revisions. Unknown/repeated/out-of-order phases, invalid terminal completion and excess events fail. Maximum retained history is six events per file plus three terminal allowance events; read sequentially with bounded state rather than collecting all JSON payloads.

The existing append-only journal triggers retain content. A unique stream anchor plus indexed scope lookup avoids repeated scans of unrelated history. Each append transaction checks the exact immutable anchor and expected event count before inserting; competing/stale adapter instances fail. Advance cached progress only after SQL commits. Existing FULL synchronization/WAL/catalog actor ownership remain in force. Records are data, never approvals. Reopening a stream with history causes the engine to refuse blind execution; recovery still inspects actual native identities and complete bytes and does not publish, delete or append success.

The general catalog readers accept shared Connection references so these validated reads run inside a catalog transaction. No schema/dependency API is exposed to the renderer. Native process-local scope leases and the existing pre-I/O budget still surround generated copy/inspection work.

## Evidence and remaining gate

The scope-free native executor diagnostic now also creates two disposable catalogs with a generated JPEG/companion, actual retained draft, reviewed bundle and compiled manifest. Fixture inventory is inserted for those generated bytes, as in the existing metadata tests; this does not claim native scanning or a production copy user flow. Execute/interrupt through the actual catalog actor, reopen stream evidence, compare published bytes, reject replay and independently check source/neighbor bytes. The completed case has thirteen events; interruption after publication has five. These extra fixture verification reads are diagnostic baseline checks, outside the production operation stream.

Regressions cover actual SQLite completion-write denial after publication without invented completion, foreign manifests/changed mappings/revoked grants, competing writers, unknown/oversized retained events and a consistent independently opened catalog snapshot. Snapshotting the catalog does not back up the media or establish independent-device recovery. Existing nine-boundary process exits exercise the original owned journal; the adapter-specific continuation below records the catalog actor's separate process-exit coverage and platform limits. Do not conflate the two adapters' evidence.

Production multi-root/nested ready-plan binding, explicit session approval, catalog/job state transitions and controls, application/output-volume capacity, fidelity acknowledgement, import/idempotency and undo remain open. All original-file mutation and M4 exact-version recovery gates remain closed; M2/M3 are not accepted. Actual check/native outcomes belong in the implementation log.

Primary SQLite contracts: [CREATE INDEX](https://www.sqlite.org/lang_createindex.html), [unique partial indexes](https://www.sqlite.org/partialindex.html). Existing pinned SQLite/Rust dependencies and helper manifest are unchanged.

## Catalog actor process-exit matrix — 2026-10-31

The catalog adapter now has its own test-only child-process matrix at all nine central-engine boundaries: intent, stage creation, copy chunk, flush, staged verification, publication intent, publication, item commit and plan commit. Before spawning, the parent binds the actual retained stream and closes its Library/catalog actor. The child accepts only the constructor-owned temporary-root prefix/UUID marker, fixed generated JPEG/companion/neighbor bytes, single-link objects, contained native roots and matching catalog root paths/record mappings. Read the marker with a bounded no-follow native handle; no supplied library path is adopted. Hidden Windows children exit with code 77 before destructors. The parent reopens the actual catalog, inspects files twice, checks expected states, refuses replay without journal growth and independently verifies source/neighbor bytes. The after-chunk case can already be fully staged because its generated JPEG fits one chunk; recovery determines this by complete comparison rather than a phase label.

These local Windows tests pass, including the reopened actor's FULL/WAL history. Native platform CI still must validate them. This supplements the owned-journal exits; it does not establish power-loss durability, independent backup, production ready-plan approval, jobs, import or undo. Production mutation remains disabled.
