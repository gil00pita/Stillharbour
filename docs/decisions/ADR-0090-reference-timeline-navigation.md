# ADR-0090 — Reference timeline navigation over bounded catalog pages

Date: 2026-11-05. Status: owner-requested scrollbar correction; actual checks in IMPLEMENTATION_LOG.md.

The owner asks for the behavior of alumbo/react-timeline-vertical-navigation, rather than the earlier month-based visual approximation. Its Stencil source in relyfe/timeline-vertical-navigation (9e7849dba58e6e21779ce334d362d4f47f7beaa9) selects the nearest photo-array index on press and every drag move. Years use the index of their first photo, with 4px filler dots at 12px intervals. Hover previews independently; gallery scrolling updates the selected position. The earlier implementation spaced all months equally, delayed distant navigation until release and unmounted its rail while replacing pages.

Use the same ordinal/interaction model in React 19 while keeping Stillharbour's bounded catalog feed. Do not load every photo/date into the renderer or install the wrapper's React 17 dependency graph. Add a typed, read-only seek_index command (chronological query, u32 index, 1–240 page limit). Resolve a stable ID through the existing validated SQL scope/order, then use the existing identity/page path. Out-of-range indices clamp to the last actual match. A concurrent catalog change can invalidate the ID and reports the existing typed failure; it never grants file authority.

Chronological pages carry optional startIndex metadata, also on packed v1 pages. The 27-field asset tuple and catalog schema stay unchanged. Prefix counts use the same query filters and date/id ordering, including ties, missing policy, GPS place scope and Undated. Retained pages propagate their first page's rank; the viewport reports the visible asset's actual rank. Ordinal lookup/prefix counts can scan the matching index; memory/page bounds do not establish a large-catalog latency guarantee. Existing performance gates remain open.

Keep the same-query gallery/rail mounted during navigation. Replacement requests have one active operation and one replaceable latest pending target. Dispose stale responses; filter changes cannot display the previous filter's assets. Use actual loaded-row geometry for targets within the retained window; otherwise seek directly to the ordinal. Keep a requested marker until the new page is available instead of snapping to the old page. Release ends tracking; Escape/cancel/blur stop subsequent movement without undoing already committed live navigation.

Use immediate active visibility for native occlusion safety, and match the source's 24px end insets/date label, 40×1px selected line, 72×2px preview underline, blue dark-mode lines, dark labels and delayed idle fade. Reserve its 56px inner lane within the gallery rather than fixing an overlay across desktop chrome. Retain system typography, native keyboard/ARIA/wheel access, reduced motion and bounded date summaries. Handle empty/single-photo inputs without the upstream division-by-zero edge case. No online fonts, original-file operations, schema changes, helper or dependency upgrades are added.

Retain the upstream MIT notice in public/licenses/timeline-vertical-navigation-MIT.txt; Vite copies it into the production frontend/native embedded assets. This is a reference-aligned React/native adapter, not a claim to ship an unmodified Stencil component or to reproduce its known pointer-release/accessibility bugs.
