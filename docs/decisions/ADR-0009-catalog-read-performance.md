# ADR-0009 — Bounded catalog read performance

Date: 2026-10-28. Status: accepted for P1 only, following the owner's “Move to next plan” instruction. Measurements and outstanding gates: [PERFORMANCE_P1.md](../PERFORMANCE_P1.md).

Keep the existing Tauri/React/Rust/SQLite architecture, schema2, authoritative writes, source guards, full open-time integrity/foreign-key validation and FULL durability. P1 changes catalog reads and their transport; it does not authorize P2–P4 or preservation operations.

The real 10k boundary-neighbor regression read16,510,976 logical pager bytes. Parameterized EXPLAIN showed a root-index skip scan plus a temporary sort for the global forward LIMIT1. Matching the visible partial-index predicate and narrowing the query to IDs alone did not eliminate that plan. For simple inventory browsing, require the existing ordered index selected from a backend allowlist. Capture sort chooses the visible timeline, general timeline or root timeline according to scope/missing visibility; other sorts use their existing indexes. Selective directory/name/tag/size/date/favorite predicates retain the planner's alternatives. No renderer-supplied SQL/index name is accepted. This is an explicit plan requirement: missing/ineligible indexes cause a typed error, never a silent fallback or schema repair. Recheck plans and the pager-budget regression after SQLite/schema changes. [SQLite describes INDEXED BY as a requirement and last resort](https://www.sqlite.org/lang_indexedby.html); this choice follows a reproduced regression and narrower unsuccessful alternatives.

Page/seek/neighbor SQL selects the27 display fields rather than native path blobs, raw metadata, digests and scan bookkeeping. Native page responses use PackedAssetPage format1 with27-position typed rows, generated from Rust alongside the request/response bindings. The renderer decodes once at the IPC seam into the existing AssetPage. Keep every configurable text-column/viewer field and non-lossy byte strings; a minimal photo-only DTO would add hydration and view-transition complexity without current evidence. A shared golden fixture is checked by Rust encoding and TypeScript decoding. Unknown formats/oversized pages fail explicitly. Any field-order change requires a new wire version and decoder. Internal catalogs and saved preferences do not change.

One ReadCache lives with each database worker. It retains counts and timeline buckets only, with LRU bounds of16 entries and512KiB encoded keys/values. This is an encoded retention budget, not an exact allocator/RSS promise. A larger result is returned without retention. Cache identity is the validated complete query hash plus summary kind. total_changes64 invalidates after any worker write, including writes without a library revision bump; PRAGMA data_version also observes external commits. Both are read on the owning database thread before lookup. No cache crosses catalog lifetimes. Preview/access/selection writes conservatively invalidate summaries too; this may limit gains during active work but avoids stale data. Selection membership, integrity verification and preservation evidence never use this cache. Seek totals and rows now execute in one worker call.

Alternatives rejected: new indexes/schema migration or dependency upgrade without a reviewed migration plan; weakening startup validation; reusing approximate counts for selection; unbounded frontend caching; removing table fields; adding a new framework. No new dependency/native binary/license/build flag is introduced. Default diagnostics remain disabled. Existing retained-version/recovery and native-platform gates remain mandatory.
