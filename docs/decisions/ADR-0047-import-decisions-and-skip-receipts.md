# ADR-0047 — Retained import decisions and fresh verified skip receipts

Date: 2026-10-31. Status: experimental M2; complete checks and Windows native validation pass; macOS CI pending.

## Decision

Save an explicit copy-or-existing-group decision for every connected confirmed bundle. Retain the original manifest IDs and target assignments unchanged. Bind selected keeper IDs to backend-only native parent locators, objects, versions, lengths and root/volume/scan evidence from the completed comparison. Incomplete comparisons cannot seed these decisions. Source and keeper membership/version checks precede saving. Reconstruct connected native grouping when validating retained/imported records; a recomputed JSON digest alone is not bundle evidence.

Store bounded immutable `import_selection_plan_v1` records in the existing catalog journal (schema 6). Limit evidence to 1 MiB and 64 decisions per draft; expose up to 32 recent plan summaries and attempt records. Equivalent decisions reuse their existing record. Every decision covers each selected file exactly once and keeps companions together. Display/native strings remain distinct. Read-only history validation is independent of current root availability; execution revalidates current grants and native objects. Preserve the existing managed grant requirement for ordinary organization copying.

Implement only the all-existing execution class in this slice. Mixed copy/skip plans can be reviewed/saved but cannot execute yet. An eligible plan's availability flag describes this class, never approval. After explicit source-retention acknowledgment, issue a separate ephemeral monotonic ten-minute single-attempt ticket bound to the action, plan ID/digest and source-root ID. Start is a distinct request. A wrong valid digest consumes the recognized ticket. Release unused grants when the plan closes; imported records or restart never restore them.

All-existing execution creates no destination namespace or output and never modifies a source/keeper. Before recording completion, freshly compare complete source/keeper bytes through the shared paced I/O budget, bounded worker gate and native read leases. Check current indexed membership/revision/length/media-primary eligibility, native parents/objects/versions, scope availability and original direct-witness digests. Recheck all compared members at the end. A stored fingerprint or historical receipt never substitutes for the new comparison. Distinct retries make fresh comparisons and retain their own attempt history without new copies.

Record an immutable queued `import_skip_attempt_v1` before starting the worker and a separate `import_skip_outcome_v1` after verification. Complete results require a durable outcome. Journal denial reports failure; an attempt without an outcome opens as needs recovery and never replays. These records describe observed files at completion time, not a permanent assertion of keeper availability. Preserve typed errors. Cancel on user request, view disposal or maintenance of any source/comparison root. Release leases, pause ownership and worker admission before publishing terminal state. Retain at most eight live-session handles; disposal drops only ephemeral handles after safe cancellation, retaining journal history.

## Interface and validation

Use ID-only typed requests for decisions, history, explicit approval/start, polling/cancel and disposal. The frontend checks complete bundle/source coverage and corresponding keeper evidence, rejects foreign plans/sessions, revokes late approvals and cancels valid late sessions. No action reports success until the backend records it. Saved drafts expose a separate read-only history entry that opens the original retained manifest without rebuilding companion decisions or compilation. History can be opened without replay; another verification requires acknowledgment and new approval. The existing experimental feature remains off by default, and all original mutation/quarantine/recovery gates remain unchanged.

Focused generated tests cover native whole-bundle binding, source/keeper changes, stable decision reuse, false digests/ticket replay, new session after restart, historical receipts with offline keepers, canceled work, repeated fresh reads, absent outputs and denied completion journals. Component tests cover explicit choice/approval/start, split-bundle and foreign-session refusal, stale errors, incomplete history without replay and late approval disposal. Native acceptance uses a separate constructor-owned valid JPEG/sidecar pair with a complete real scan and coherent renamed stem; malformed/unsupported comparison coverage remains a separate fixture. Audit originals, both candidate files, existing outputs and neighbors independently. Complete/native outcomes follow in the implementation log.

This slice does not complete folder import, mixed copy/skip, multi-root organization, cross-volume/case-cycle/undo or M2. M3 still requires the M2 gate.
