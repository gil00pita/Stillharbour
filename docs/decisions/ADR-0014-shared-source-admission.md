# Shared atomic admission for read-only source work

Independent media semaphores let background metadata and thumbnail prebuild compete with visible previews without priority or volume coordination. Replace their media admission with one backend-owned scheduler per Library, acquiring the source, CPU and estimated memory reservation together. Retain separate job/maintenance gates. Atomic admission avoids holding a CPU permit while waiting for a source permit; no lock is held over filesystem/helper work.

Start conservatively: two active source steps globally, one per known native volume, 384 MiB estimated reservations (64 MiB metadata, 192 MiB rendition), and at most 64 waiting requests. A volume of zero conflicts with all active sources. Native volume IDs merge roots on the same volume but cannot establish physical-device independence across APFS volumes or NAS aliases. This is not complete physical/endpoint mapping or a byte-rate/RSS guarantee. Existing decoder limits/watchdogs remain authoritative. Enumeration, catalog/cache reads and helper-internal buffering are outside this admission accounting.

Visible requests precede unaged background requests; after 500 ms ready background work joins oldest-first service. Aging does not preempt running helpers, make blocked source requests runnable, or promise a wall-clock deadline. Recheck all predicates after condition-variable wakeups and poll queued cancellation at 20 ms. A lease remains charged until its owner finishes or fails; queued cancellation does not assert that a running codec stopped. Existing helper supervision and durable job states retain that responsibility.

Use the virtualizer's existing moving/settled signal to request only visible tiny renditions while scrolling, then clear tiers and bounded overscan after settling. Keep already displayed layers. No new speculative viewer reads are added. There is no production backup adapter; generated read contention is explicitly a fixture. Transfer token buckets, live rate controls, physical endpoint mapping, NAS/HDD tests and mutation-safe commit scheduling remain gated. See [PERFORMANCE_P3.md](../PERFORMANCE_P3.md) for evidence and limits.

Predicate-loop behavior follows the [Rust condition-variable contract](https://doc.rust-lang.org/std/sync/struct.Condvar.html). Existing helper containment is retained because [Tokio blocking work cannot be aborted after it starts](https://docs.rs/tokio/latest/tokio/task/fn.spawn_blocking.html). These primary references inform implementation; they do not prove the app's performance or safety tests passed.
