# ADR-0013 — Live read-only library reconciliation and observed changes

Date: 2026-10-29. Status: accepted for the owner's live Gallery/Folders request; native evidence remains platform-scoped.

Filesystem notifications are hints, not catalog truth. Debounce native notifications and reconcile through the existing identity-checked, no-follow scanner under its one-scan/two-media limits. Add pinned notify 8.2.1 (MIT OR Apache-2.0) for native platform notifications, with no secondary state framework or decoder. Ignore access-only events. Coalesce each watched root into constant-size atomic state; never queue file paths. Watch at most 64 roots, with periodic reconciliation for other roots or failed watchers. Recheck online roots after restart and periodically to cover missed events/network filesystems. Root identity/volume mismatch requires relinking; offline/inaccessible roots retain inventory. This does not implement P3 scheduling.

A change is a catalog observation: Added, Moved, Updated, Removed or Reappeared. Removed means absent from a successfully enumerated scope, not app deletion or recoverability evidence. Moves preserve IDs/annotations only with the existing unambiguous same-root native-file/birth evidence. Cross-root moves and ambiguous identities remain separate observations. No content-hash deduplication or claim of original fidelity follows.

Persist versioned change records transactionally with inventory updates in the existing generic job_events journal, under the reserved library-change:<root UUID> namespace. This avoids a user-catalog schema migration or separate inconsistent history file. The payload retains root label, asset ID, observed paths/revisions, scan ID, kind and time; display paths never become execution inputs. Initial discovery establishes a baseline; later differences are journalled. History is local catalog data, not telemetry. Retain history across restarts, ordinary rescans and catalog root forgetting; no automatic history expiry. Read history through sequence-keyset pages of at most 100 items and show it in the existing Jobs dropdown.

Normal Gallery/Folders hide confirmed missing observations. Explicit gallery missing-history filtering remains; offline/inaccessible observations remain visible. Mark absent directory branches missing only when their ancestor's successful enumeration proves absence. A user already inside a removed folder sees a truthful unavailable state and can go Up. Keep bounded feed refresh, selection and stable anchors; original-dependent viewer behavior remains explicit.

Native APIs cannot promise instantaneous or complete notifications. Fallback checks and scan duration bound eventual freshness, not an atomic filesystem snapshot. Native traversal on Windows remains unavailable until its separate safety tests pass. Tests use only generated/owned fixtures, with independent source manifests around read-only reconciliation and explicit externally simulated changes.

Primary references: [notify 8.2.1](https://docs.rs/notify/8.2.1/notify/), [configuration](https://docs.rs/notify/8.2.1/notify/struct.Config.html), [event rescan flags](https://docs.rs/notify/8.2.1/notify/struct.Event.html). Network filesystems can omit notifications; never turn that absence into proof of no changes.
