# ADR-0010 — Read-only native format previews

Date: 2026-10-28. Status: accepted for the owner's explicit HEIC/CR2/common-preview request, a bounded M5 format slice. This does not authorise all M5, maps, metadata export, original operations or P2–P4.

Retain baseline JPEG/PNG/WebP decoding and the isolated byte-input worker. Add a macOS ImageIO/CoreGraphics adapter for selected native types, with explicit ColorSync rendering into sRGB RGBA8, orientation once, no upscaling and primary-image/first-animation-frame previews. Native camera rendering is a preview, not proof of complete RAW validity, full-resolution color fidelity, HDR or duplicate equality. Windows and other codec/camera/OS combinations require their own packaged gates.

Use a small C bridge linked into the existing executable, not an external tool or arbitrary filesystem interface. It accepts byte buffers only, validates 32 MiB input, 12000 px dimensions and 128 MiB source-RGBA estimate, writes into a caller-owned ≤512 px buffer and releases native objects on every exit. Preserve the 12-second parent deadline, cancellation, bounded output/queue/admission and protected cache publication/read-back. Add a direct-child RSS watchdog with fail-closed monitor errors and a 512 MiB/25 ms sampling policy; this detects excess after sampling and is not an instantaneous OS sandbox or complete XPC/process-tree guarantee. Never weaken the existing limits to make a fixture pass.

The only Cargo graph change is a direct build dependency on the already locked cc 1.10.0 (MIT/Apache-2.0); no version upgrade. Its checksum remains the existing lock authority. Compile the owned C bridge as C11 with warnings denied and provisional macOS 13 deployment flag, using the installed Apple SDK. Runtime decoder implementation belongs to the OS; record actual OS/SDK/architecture in FORMAT_SUPPORT.md. No HEVC/LibRaw binary or new codec license is bundled. Existing clean-machine/signing/minimum-OS gates remain.

Use policy `m5-v2-oriented-native-srgb8-preview`. A fixed numeric RAW hint derived from the guarded native filename extension lets ImageIO distinguish camera RAW from generic TIFF. The renderer still supplies only asset IDs; no arbitrary UTI, path or shell interface is added. Explicit baseline ICC fallback first requires ColorSync profile verification; malformed profiles remain rejected.

Bump the thumbnail processing policy. Version negative preview errors in the existing preview_error text field, stripping the internal envelope at the catalog projection. Legacy/other-policy failures become retryable observations; current-policy failures remain suppressed to avoid render-triggered retries. Positive cache keys already include the policy. Accept indexed, existing M1 positive previews under their exact prior policy: the unchanged untagged JPEG/PNG/WebP output contract is compatible, preserving offline browsing without copying, purging or regenerating those files. Do not bulk-rewrite catalogs, migrate schema, purge previous cache objects or require original changes. Catalog UUID/schema/root identities remain unchanged. Independently verify source fixtures before/after including failures. Record actual format/camera successes and unsupported/over-budget cases separately; no universal extension promise.

Alternatives deferred: libheif/LibRaw distributions and patent/license/platform packaging; renderer original-file URLs; unbounded native full-image decoding; source conversion; automatic cache clearing; a schema migration solely to version derived failure state.

Primary references: [Apple ImageIO](https://developer.apple.com/documentation/imageio), [image source/thumbnail options](https://developer.apple.com/library/archive/documentation/GraphicsImaging/Conceptual/ImageIOGuide/imageio_source/ikpg_source.html), installed SDK CoreGraphics/CoreFoundation/ImageIO/libproc headers. Fixtures must be generated or explicitly licensed public camera samples with pinned hashes/provenance, never a personal library.
