## Transport and failure evidence

The final Windows application-adapter round trips pass for local, SMB, SFTP, FTP and FTPS. Each uses generated sources, the actual application catalog, OS credentials, full checks, generated-source removal, new-output restore and byte/catalog/history/neighbor audits. Actual queued jobs reject wrong remote credentials, changed SFTP trust and missing FTPS trust. Receipts are `.context/m4-final-application-transports.json` and `.context/m4-final-application-ftp-transports.json`; the former retains its earlier FTP environment-setup failures.

The actual local FTP/FTPS five-scenario failure matrix passed all ten preservation checks in 581.971 seconds (.context/m4-application-failure-final3.json). Interrupted disconnect/quota cases now stop promptly and preserve existing objects, but retained locks may block post-fault checks and restore. Such outcomes are `preserved_unresolved_lock`, with post-fault recovery false. Expired credentials, lost publication acknowledgment and corrupted newly uploaded packs have distinct assertions; no generic error counts as a pass. The new actual SFTP and SMB growing-pack upload-disconnect cases also passed, in 60.100 and 65.680 seconds; both remain explicitly unresolved under retained repository locks. The bounded opaque TCP proxy proves positive new-pack growth/forwarding and audits final native objects; it does not model physical unplug or prove protocol-level write prevention. [Application acceptance](M4_APPLICATION_ACCEPTANCE.md) records per-scenario outcomes.

Both-platform helper-only transport CI passed at `434c0ce` ([41373547497](https://github.com/gil00pita/Stillharbour/actions/runs/41373547497)); that remains historical helper evidence. Actual [application transport CI at 67428ed](https://github.com/gil00pita/Stillharbour/actions/runs/41397152943) now passes both Windows and macOS: five normal application round trips and ten FTP/FTPS failure checks per platform.
