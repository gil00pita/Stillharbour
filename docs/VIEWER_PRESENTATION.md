# Page-scoped photo viewing

Owner request: 2026-10-30. Expand the clicked photo into the page, keep the menu visible, close with a reverse zoom from X, and show a moving glare while a preview loads. Also address the attached gallery's “Cached preview failed to load” state. This is an M1 presentation/recovery refinement, preserving the earlier initial-preparation work and all original-file gates. [ADR-0017](decisions/ADR-0017-page-photo-viewer.md) records the boundary.

## Behavior and implementation

Photos/Tags and the Folders explorer keep their mounted page underneath a nonmodal native HTML dialog positioned inside the page container. The sidebar remains visible and usable; covered page controls are inert and hidden from assistive navigation. Focus starts on the labelled X. X and Escape close the viewer, with Escape dismissing Info first when open. Clicking the photo or background never closes it. Menu navigation can leave the page normally and cancels outstanding animation work. Existing filtered neighbors, catalog-only notes, filmstrip, 100–400% fit-relative zoom/pan and focus/scroll return remain.

Owner icon refinement (2026-10-30): Previous/Next use matching stroked arrow icons in 40 px controls. Keep “Previous photo” / “Next photo” accessible names, hover titles, keyboard behavior and unavailable-neighbor disabled states.

Reuse the clicked loaded rendition for immediate continuity. Measure its actual contained bounds, fit a single image frame to the viewer plane, then animate translation/scale with the Web Animations API: 250 ms in, 150 ms out, smooth deceleration. Close targets the current photo's visible tile; absent/unloaded/offscreen tiles use a quiet local scale/fade. No transform reaches the sidebar because the page clips it. Cancel animations/observers/timeouts when navigating/unmounting; a bounded completion guard handles occluded windows. Reduced Motion and hidden windows skip spatial motion. The zoom reference is [react-medium-image-zoom's gallery](https://rpearce.github.io/react-medium-image-zoom/?path=/story/galleries--image-gallery); this uses the existing viewer instead of installing its whole-window dialog/click-to-dismiss behavior.

A low-contrast diagonal sheen covers the image only while a request/image element is loading, including when a smaller rendition is already visible. It is driven by loading, never hover, and disappears on actual high-image load or terminal failure. The status remains textual; hidden windows pause the sheen and Reduced Motion uses a static highlight. Inspiration: [React Bits Glare Hover](https://reactbits.dev/c/animations/glare-hover) and its [primary CSS source](https://github.com/DavidHDev/react-bits/blob/main/src/content/Animations/GlareHover/GlareHover.css). No imported component, dependency, shader or pointer tracking is needed.

## Cached-image failures

The reproduced regression is a permanent frontend latch after one image-element error: the tile removes its clear image and cannot recover while mounted. The focused red test fails with a missing retried image (1.17 s). It reproduces that persistence mechanism; it does not establish which source/cache/transport event triggered each private image in the owner's screenshot.

Share one CachedPreviewImage adapter across tiles, viewer layers, filmstrip and Compare. Retry a failed owned-cache URL once with a query suffix; a second failure reaches the existing fallback/error handling. Source/revision/edge changes reset this bounded attempt. Gallery terminal failures offer an accessible sibling Retry preview button, outside the image's open button. Explicit retry clears stale ready statuses before requerying the existing bounded native pipeline and remounting the requested visible tiles. No automatic original-file scan, cache purge, unknown-file deletion or corruption repair is introduced. Missing owned previews can regenerate through the existing guarded native queue; inaccessible originals, unsupported formats and invalid cache files remain explicit failures.

The native protocol marks 404 responses `Cache-Control: no-store`; successful revision/policy-keyed PNGs retain their positive cache policy. Query suffixes affect transport caching only; the same four validated path fields govern native reads. [Cache-Control guidance](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Cache-Control) and [Element.animate](https://developer.mozilla.org/en-US/docs/Web/API/Element/animate) are the primary API references.
