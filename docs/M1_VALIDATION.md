# M1 read-only library validation

Authorised by the owner on 2026-10-27 with “lets start with the next phase”. This is the bounded M1 task, following M0. Original-file rename, move, delete, import execution, backup and embedded metadata writes remain unavailable. Saving managed mode does not bypass that guard.

## Implemented scope

Native selection → saved base/additional roots → real background scan → persistent chronological gallery, uniform grid and text-only list. Root filtering, tag-based include/exclude patterns, hidden switches, scan size restrictions and browsing date restrictions, job cancellation/issues, metadata provenance, bounded preview workers/cache, keyset pages, direct year navigation, inspector and catalog-only favorites/ratings/tags are connected to Rust/SQLite. Map and file utilities have honest unavailable states; Albums / Tags currently implements tags, not saved albums.

Schema 2 retains catalog UUIDs and takes a consistent, independently openable snapshot before migrating an existing v1 catalog. Sources remain ordinary folders. Scans store full regular-file inventory, including companions, and browse media entries. Missing requires authoritative directory coverage. Offline/inaccessible roots and incomplete scopes retain inventory. Reconnect/restart reconciliation starts fresh read-only work. Native relative paths are lossless; renderer paths cannot grant filesystem authority.

## Environment and commands

Local environment: macOS 27.0.1 arm64, Apple M1 Max, 32 GiB RAM, APFS local temporary fixtures, SQLite 3.54.1. All scan tests create and own temporary media; no user photo library was used as a development test. Names, bytes, directories, links and companion bytes are compared before/after. The OS may update access times during reads; the application does not rewrite original content or metadata.

Evidence is under `.context/evidence/` and native screenshots under `.context/screenshots/`. Run:

```sh
npm run check
npm run desktop:test:build
npm run desktop:test
npm run desktop:build
npm run release:check
node scripts/cargo.mjs run --release -p stillharbour-core --features fixture-probes --example library_probe
```

The native suite drives real WKWebView, library IPC and cached PNG protocol. It substitutes only picker presentation with a backend-issued selection for a generated folder. It does not claim OS picker interaction was automated. Test commands, request-observation events and servers are excluded from production.

## Format and platform limits

JPEG/PNG/WebP previews are exercised locally with EXIF orientation and bounded dimensions/allocation. ICC-managed images are explicitly refused pending color transformation tests. Animated/multipage completeness, RAW/HEIC/video previews and color-fidelity matrices are not claimed. Inputs over 32 MiB or dimensions over 12,000 are retained in the catalog with an explicit unavailable state. A thumbnail is not a deep integrity check.

ExifTool 13.55 code is packaged, checksummed and licensed in `vendor/`; it uses explicit system Perl on macOS. Clean-machine, minimum macOS 13, Intel, Windows, notarization/signing and standalone Perl distribution remain open gates. This original macOS evidence predates the Windows adapter; the later NTFS continuation below supersedes the former Windows scan block only for its stated local scope. This milestone does not establish cross-platform release readiness.
