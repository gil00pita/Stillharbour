# ADR-0065: Explicit source-root copy partitions

Date: 2026-11-01. Status: implemented; complete local and Windows native validation passes. Its own target CI follows the checkpoint.

Keep a multiple-library selection as one immutable complete confirmed manifest. Require an explicit managed source root for each execution review. Capture only that root's exact members in a native snapshot while retaining the complete manifest ID/digest, owner identity and destination grant. A nullable root_partition marker distinguishes these scopes; absent fields preserve existing single-root serialization. Reject a partition on a single-root manifest, foreign/missing roots, extra/missing members, changed native bindings and partition/import-projection combinations. Global manifest conflicts remain blocking. Schema 8 and dependency lockfiles are unchanged.

Each root has a separately previewed new output namespace, preparation approval/job, copy approval/job and effect history. The UI says a completed job covers only that root. This is not an atomic all-roots operation. Keep existing bounded sessions/jobs and native registry leases; never combine root grants into a common ancestor. Capacity uses the exact subset while fresh confirmation rechecks the whole retained manifest. Root changes retire the prior UI review and inactive session; active jobs prevent selector changes. Foreign-root reviews cannot enable approval. Referenced/offline/missing roots remain blocked in this ordinary copy path; the separate import path retains its existing rules.

Earlier partitions create sibling output folders in the same destination. Their historical unprefixed draft target observations are not later partitions' write scopes. Explicit partition reviews use the existing prepared-assessment path: retain all fresh source, destination identity/volume/grant, overlap and capacity checks, then preview an exclusively owned namespace with its own immutable facts. Native preparation still performs exact name equivalence/no-replace checks before publication. This policy does not reuse historical observations to overwrite an existing output.

The first integration test caught a retained single-root assumption in CatalogJournal: its repeated source-grant check selected the complete manifest's first root. It safely refused a partition belonging to the other root. Resolve the root from the validated prepared namespace binding for both initial copy and approved continuation; retain the direct single-root compatibility validator. No grant check is removed.

Exercise an owned isolated process with separate root approvals/jobs, subset capacity and full-manifest preparation reopening, modified partition/refused grant cases, complete output/source/neighbor verification and distinct idempotent history. Component tests exercise explicit choice, typed root requests, cross-root response rejection and draft retirement. Extend native desktop smoke using two newly generated LibraryFixture instances, actual registered/scanned managed roots, real saved-plan/companion/copy UI and a constructor-owned destination. The diagnostic accepts no paths/root IDs/content; its independent audits verify each source baseline and target bytes. Production excludes these fixtures. Record actual full/native results in the implementation log. Multiple-root import comparison, general original-operation orchestration/restart and other M2 gates remain separate unfinished work before M3.
