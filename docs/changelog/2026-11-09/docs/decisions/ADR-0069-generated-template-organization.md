# ADR-0069: Template organization in the owned native scope

Date: 2026-11-01. Status: implemented; validation recorded in the implementation log.

M2's generated rename lifecycle previously used only fixed case/cycle mappings. Connect the existing pure organization resolver to the same closed five-member constructor, catalog, worker, review, approval, recovery and reverse planner. The renderer supplies a typed template policy, never source paths or a library grant. Keep the fixed case/cycle constructor for its existing regressions.

Resolve the four primary generated names in the existing stable sequence order. The payloads have no capture metadata: missing-date policy applies without fabricated EXIF. Derive the fifth same-stem XMP name with the existing companion target resolver. Reject blocked, nested or native-conflicting targets before admitting an executable session. Folder templates remain available through source-retaining copy; this generated in-place adapter handles one parent.

Retain the optional frozen template in the private recovery scope. Absent fields preserve the earlier fixed-scope record. Cold reconstruction recomputes every target from the policy and fixed source names before checking native objects, retained bytes, canonical graphs and catalog identity. Existing immutable record hashing and approval retirement still apply. No alternate executor or replay path is introduced.

The desktop-test lab exposes editable filename/event fields before construction, exact target review, separate approval and undo. Its native scenario uses this path through stop, owned reopening, fresh continuation and undo; fixed case/cycle probes remain separate. Component mocks establish UI behavior only. Actual target tests are required before claiming native success.

This is disposable-fixture integration, not general adoption of existing libraries, arbitrary folder renaming, independent recovery, codec support or production mutation authorization. No schema, dependency, permission or application identity changes.
