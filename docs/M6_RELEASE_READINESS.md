## Initial scope and evidence

This first pass inventories all [85 AC and 40 PS obligations](M6_EVIDENCE_MATRIX.md), reviews the production boundaries below, hardens build preflight and adds an [in-development user guide](USER_GUIDE.md). The matrix separates historical implementation evidence from eventual signed-package acceptance. It does not turn a prior CI pass or an existing test name into a new native result.

The production preflight previously accepted an empty JavaScript inventory: every forbidden-marker search succeeded against an empty string. Its dependency check excluded WebDriver packages but did not inspect enabled features; an actual graph with `copy-workflow,backup-workflow` passes that old check. New regression fixtures reject these states, empty entry points/chunks, source maps, linked build inputs, nested instrumented chunks and missing/experimental feature inventories. The normal default graph remains accepted. Logs: `.context/m6/preflight-before-after.log`, `default-graph.txt`, `experimental-graph.txt` and `release-policy-tests.log`.

`npm run test:release` runs these isolated Node tests and is included in `npm run check`. `npm run release:check` now inspects Cargo's resolved features as well as package names, using `--locked`. Both owned packages may expose only their empty/default feature set in this preflight. Enabling any other feature requires a separate reviewed change to the policy and supporting acceptance evidence. No application capability changes here.

The preflight reads a quiescent workspace build tree. Link/special-file refusal is a build-input check, not a race-proof filesystem authorization mechanism. It inspects `dist`, configuration, helper manifests and the host default dependency graph; it does **not** inspect an installed/signed package, prove compiler output provenance or certify release readiness. Cargo itself describes its tree as an approximation of compilation; retain exact build flags, lock hashes, artifacts and native execution for final acceptance. See the [Cargo tree format documentation](https://doc.rust-lang.org/cargo/commands/cargo-tree.html).
