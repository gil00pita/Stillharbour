# Performance acceptance scenarios — P0 evidence checklist

The named addendum checklist was absent when P0 began on 2026-10-28. This file reconstructs its P0 checks from the owner's authorised prompt, [PERFORMANCE_PLAN.md](PERFORMANCE_PLAN.md) and existing preservation rules; it does not claim to reproduce a missing external document. Proposed targets remain proposals. See [PERFORMANCE_BASELINE.md](PERFORMANCE_BASELINE.md) for actual results and evidence.

A status applies only to the stated platform/build/workload. **Passed** requires completed supporting evidence; **failed** means the stated check/target was exercised and unmet; **blocked** identifies a missing prerequisite; **not run** means no result was collected. A debug native functional pass is not a release performance pass. Do not combine those scopes into a single product claim.

| ID    | Scenario and required evidence                                                                                                                                                                                                                      |
| ----- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P0-01 | Inspect actual gallery/catalog/thumbnail/bridge/scheduler/backup implementation and identify absent prerequisites.                                                                                                                                  |

| P0-06 | Release backend pages, filters, date seeks, buckets, neighbor reads and frozen selection have defined samples, p50/p95/p99 where measured, and actual query-plan evidence. Proposed ordinary-query target is p95 <250ms at the 100k reference size. |
| P0-07 | Known-catalog warm populated gallery first paint p95 ≤2000ms. Separate validation/open time, data readiness, placeholders, decoded images and actual presentation.                                                                                  |
| P0-08 | Known-catalog text-list first useful page p95 <500ms end to end. Text mode triggers zero nonempty thumbnail/decode requests.                                                                                                                        |

| P0-16 | Identify the three largest measured costs, smallest proposed fixes and P1 prerequisites. Stop after reporting; no query rewrite, schema migration, decoder/cache policy replacement or shared scheduler implementation.                             |

## P1 — authorised catalog-read update

P0 statuses/evidence remain historical. Report these checks separately in [PERFORMANCE_P1.md](PERFORMANCE_P1.md), with platform/build/sample scope.

| ID    | Scenario and required evidence                                                                                                                                                                                                                                                  |
| ----- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P1-01 | Compact page format preserves every display field, null, exact byte string, stable ID, cursor, total and revision; Rust encoding and TypeScript decoding agree on a shared versioned fixture. Reject incompatible/unbounded pages.                                              |
| P1-02 | Keyset pages/neighbors preserve all five sort orders, equal/unknown dates, large byte counts and filter/root/directory scope. Reproduce the old boundary pager regression; verify the ordered plan and bounded logical page reads after the fix.                                |
| P1-03 | Count/bucket LRU has entry/encoded-byte bounds and no cross-catalog lifetime; changing scope cannot reuse another query. Worker writes, including those without a revision bump, and external commit observations invalidate summaries. No selection/safety evidence is cached. |
| P1-04 | Catalog-only warm pages, seeks and summaries work with offline synthetic roots without source enumeration. Do not infer NAS throughput, network profiles or real original availability.                                                                                         |
| P1-05 | Record actual release backend p50/p95/p99, sample counts, payload bytes and plans at10k/100k/1m with explicit cold/warm definitions, linked SQLite/build identity, source manifests and memory/I/O coverage limits. Retain P0 evidence.                                         |
| P1-06 | Native gallery/text/date jumps/resize/viewer/selection/return and bounded resident pages remain correct. UI-functional/debug evidence cannot pass release presentation, whole-process memory or Windows targets.                                                                |
| P1-07 | Independent before/after source manifests match; schema2, locks/dependencies, FULL durability, full open validation, exact frozen selection and preservation gates remain intact. No source mutations or production cache eviction.                                             |

Stop after P1. Later row/rendition/scheduler work and native release stress evidence require their own approval and gates.
