# M4 application acceptance audit

Audit date: 2026-11-02. Scope: the current M4 application integration, the 40 scenarios in [PRESERVATION_TESTS.md](PRESERVATION_TESTS.md), and AC-066–073/081/084 in [ACCEPTANCE_TESTS.md](ACCEPTANCE_TESTS.md). This is an evidence map, not an all-M4 acceptance certificate. Stop before M5 remains applicable.

The owner authorized all M4 stages and generated local disposable servers. That authorization does not satisfy an untested preservation gate. Default production backup execution remains gated. Windows native tests now cover private old-destination snapshot admission/restore and a bounded native metadata policy. A generated C:/E: round trip also proves that the actual independent-device classifier can admit those distinct devices. These results do **not** constitute a strict old-destination replacement certificate: production OLD review does fresh metadata capture/digest comparison, but this Windows host cannot prove audit-security fidelity (`ACCESS_SYSTEM_SECURITY` fails with native error 1314; no privileges were enabled). Tests with deliberately uncertified `RecoveryFile` objects remain correctly rejected. Synthetic replacement proofs do not supply that missing authority. The generated local Windows desktop lifecycle passes; the full preservation matrix and remaining macOS/native-provider acceptance remain open.

Application append process exits cover `AfterIntent`, `AfterStageCreation`, `AfterCopyChunk`, `AfterFlush`, `AfterVerification`, `BeforePublish`, `AfterPublish`, `AfterItemCommit`, and `AfterPlanCommit`. Application preparation faults cover stage/probe creation, names proven, probe moved and plan bound. Retained application fault tests cover retained directory creation, old/new intent/move/record and final completion; those tests use synthetic recovery proof and are not accepted production provider evidence. Snapshot actual process-exit coverage is separately recorded at eight boundaries, including inside incomplete SQLite copy, in `.context/m4-snapshot-inside-catalog-exits2.log`; untested helper/restore/metadata subphases remain open.

The native lifecycle writes `.context/m4-application/native-*/snapshot-lifecycle.json` and a desktop screenshot after history refresh. Its native audit asserts all four original baseline files recovered, a SQLite catalog present, source unchanged before intentional generated removal, and both destination-only neighbors preserved. The snapshot service additionally checks the recovered application catalog schema/UUID and full manifest bytes; a SQLite header alone is insufficient catalog acceptance. CI should retain exact command status and OS/build/helper identity alongside these receipts. Never copy a successful unrelated lab receipt into this application evidence slot.

The default desktop runner requests a real graceful native quit after each spec and confirms its PID exits, so the next embedded worker receives a fresh default test catalog. The three-launch config overrides that hook because each phase owns its explicit quit while reusing only its bounded persistent generated session. Neither test mode substitutes a webview reload for application restart.
