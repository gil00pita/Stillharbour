# Gallery row balancing — 2026-10-28

The owner requested gallery improvements informed by [Building the Google Photos Web UI](https://medium.com/google-design/google-photos-45b714dfbed1). The useful principles for this existing app are choosing row breaks across a sequence rather than greedily, keeping rendering bounded, and avoiding repeated resize work. These are design inputs, not Stillharbour performance measurements or permission to implement every future performance phase.

## Resulting behavior

- Timeline photos preserve chronological order, existing aspect-ratio bounds and 4 px gutters. A shortest-path layout evaluates alternative row breaks within each date group in the retained renderer window. It balances deviation from the selected thumbnail height and excessive whitespace, with a stronger penalty for extremely short/tall rows. Panoramas can occupy their own row instead of shrinking into an already crowded row.
- Normal rows can stretch up to 125% of the chosen target. A sparse last row of each date group never stretches above that target. Exceptional aspect ratios may leave whitespace rather than produce an excessively tall row. Tiny final orphans are discouraged, not forbidden when the photo sequence requires one. Date boundaries, unknown dates and explicit shown-group membership remain intact; no photo is reordered or hidden by layout.
- Narrow date headings use a compact month/day/year caption, retaining the full date in the heading's accessible name and title. Today/Yesterday/Unknown date keep their meaning. Counts appear only when the heading has room. The date checkbox still names the exact number of shown photos; it never selects unseen catalog matches.
- ResizeObserver notifications coalesce through one requestAnimationFrame callback, using the latest width and existing stable-ID/pixel-offset anchor. Unmount cancels pending work. This avoids repeated calculations during a resize burst without adding an arbitrary settling delay.

The initial 2026-10-28 row-balancing slice retained the TanStack virtualizer, two-row overscan, bounded three-by-240 feed, filtered month seeks, viewer/filmstrip, text-only mode, preview ownership and error/offline states. It introduced no full-catalog renderer, predictive original read, new rendition policy, scheduler, schema/IPC/dependency change or original-file operation. Separate P2/P3 work and the owner revision below record subsequent changes; historical measurements are not measurements of the updated pipeline. No 60fps, latency or memory improvement is claimed without measurements.

## Implementation and checks

It accepts only geometry supplied by [model.ts](../src/library/model.ts), which normalizes metadata ratios and available width/target. Missing dimensions remain bounded placeholders. Day membership accumulation now appends to its owned array instead of repeatedly copying a dense day.

There is no framework replacement.
