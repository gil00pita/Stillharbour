## Source access and limits

The original protocol accepts only asset ID, revision and the generated original-image policy, from the main webview with GET. The native library resolves the catalog's non-lossy path, validates registered root/volume/identity and current revisions, and checks presence/placeholder state. It reads unchanged original bytes through the existing cancellable 64-KiB-chunk/32-MiB adapter. The supervised existing worker independently decodes a tiny validation rendition to establish actual source geometry; that rendition is never passed off as the original. Reopen and reconcile source/catalog revisions after the worker. No original or sidecar is written, and the original payload never enters the preview cache.

Allow detected static JPEG, PNG and WebP at most 32 MiB and 32,000,000 pixels. Reject animated PNG/WebP, active formats such as SVG, malformed/overflowed chunk lengths and more than 4,096 container chunks. The RGBA8 estimate stays below 128 MiB; browser/OS/color/GPU overhead is not an instantaneous memory quota. Existing helper timeout, sampled RSS, source-volume/concurrency and cancellation limits remain; the validation helper's separate I/O accounting/limits still apply. One original read is admitted, with maintenance coordination and cancel_all support. Admitted work can finish after navigation; a concurrent request may fall back and be retried. Never remove resource limits merely to make a large source appear supported.

The response is byte-for-byte original image data with a detected image MIME, nosniff, sandbox and no-store headers. Both normal/dev CSPs allow only the dedicated image scheme and its Tauri Windows localhost mapping; no general filesystem/asset scope or connect capability is added. The protocol returns a non-storable error on failure. Primary API/security references: [Tauri convertFileSrc](https://v2.tauri.app/reference/javascript/api/namespacecore/#convertfilesrc), [HTML image loading](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/img), [WebP container/animation](https://developers.google.com/speed/webp/docs/riff_container) and [PNG/APNG chunks](https://www.w3.org/TR/png-3/).

## Viewer behavior

Keep already-generated pixels beneath the original while it loads, with the existing loading-only glare and textual feedback. Show the original only after its image load event, hide the fallback from visual/assistive navigation and enable zoom based on original readiness even if cached tiers failed. The normal loaded original has no cached-preview disclaimer. Offline, unsupported, over-budget or failed source loads retain an explicitly labelled preview and Retry original; the fallback tooltip states the format/size envelope. This is original-byte display for the admitted formats, not RAW/HEIC/TIFF support, an integrity claim or archival color-fidelity certification.

X is the last toolbar control, on the right, and keeps its accessible Close photo viewer label and reverse animation. The bottom 44-pixel heart uses aria-pressed and an explicit favorite tooltip. Disable it during a catalog save. Fill after the existing catalog write/detail confirmation; a failed write stays unfilled with an error. Successful favoriting animates fill and a short vector-preserving pop; unfavoriting clears it. Initial favorites/navigation do not replay a click animation, late responses belong to their original photo, and Reduced Motion removes motion. Favorites remain catalog-only annotations.

Install the loaded original without an extra opacity fade: an obscured native window can suspend CSS transitions even after an image load event. Share document-visibility observation with the existing loading sheen; hidden heart feedback snaps to its confirmed state. A bounded animation-completion guard also handles suspended animationend events. Visible click feedback remains animated, and the original pixel layer never waits for a decorative transition to become visible.
