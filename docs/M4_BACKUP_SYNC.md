# M4 Backup & Sync

## Current increment — 2026-11-01

The owner requested starting M4. The first M4A increment adds a real native read-only comparison workspace. M4A implementation and native validation are complete at the read-only review gate; exact-head Windows/macOS results are recorded in M4A_VALIDATION.md. M4B–D retain separate approval gates. Copying, replacement, encrypted snapshots, restore and original mutation remain unavailable.

New comparisons use the catalog's base root (`is_base`), not browsing defaults or the preferred import destination. Each session run binds catalog/root UUIDs, native identities, volume, paths, mode and policy. Saved comparison profiles retain their original source even when the base changes. Requests carry native selection/profile/run IDs, never renderer paths. Identity changes, unavailable roots, application-data overlap and overlap against every library root fail closed. Pending original recovery blocks admission. Shared operation read leases exclude owned writers. One worker per catalog has no queue; Cancel is cooperative at enumeration/read boundaries. OS calls already in progress can block. Reopening can inspect/cancel the current session run. Removal refuses its active source; shutdown requests cancellation.

The proposed dataset is `<destination>/.stillharbour-copy/<catalog UUID>/<root UUID>`. Compare creates no files or directories in either tree, including when the namespace is absent. Other destination files remain outside scope. Existing dataset contents are observed, not adopted. No helper or restic repository is invoked.

Handle-relative inventory ignores gallery filters: hidden files, companions, damaged images and unknown regular files are included without decoding. Links, special objects and placeholders produce issues. Limits per tree: 10,000 visited entries, 16 MiB estimated path/record memory, 64 descendant levels. Enumeration streams; rows page by 200 and issues show the first 200. Partial inventory cannot prove absence or produce a review digest.

Verified comparison streams complete equal-length pairs and rechecks native revisions/object membership; unequal lengths establish different content without payload reads. Quick size/known-mtime matches remain explicitly unverified. Other quick pairs remain uncertain. Reads use shared `PacedIo` at its current setting (initially 10 MiB/s); metadata, scans/previews/helpers, external processes, caches and physical traffic are outside this byte cap. Directory/file revisions are checked before final review, but this is not an atomic snapshot or immunity to external writers.

The digest binds native paths, identities/revisions, catalog/root/namespace, policy and rows. It is a session review identifier, not a durable execution plan, approval, fidelity baseline or recovery evidence. Destination-only entries propose Keep. Different content has no automatic winner. All execution/replacement/fidelity/recovery capabilities remain false. Reviews expire on restart or replacement.

## Saved comparison profiles — 2026-11-01

The next M4A increment stores up to 32 immutable comparison profiles per catalog. Save a name and a fresh native destination selection; the backend binds the current base root UUID, native source/destination bytes, device/object identities, stable volume tokens, platform and catalog UUID. Profile names are 1–80 visible characters, and each private record is bounded to 64 KiB. The renderer receives display paths only. Saving writes the catalog, never either file tree, and creates no comparison or approval automatically.

Select a saved comparison to reopen its original source/destination. Fresh comparison checks native identities/containment/availability, the stored source path and volume, and pending recovery. No fallback to the new base, no automatic relink/rebinding and no reused approval/equality result. Explicit Review profile rebinding shows previous/current scopes, requires a fresh destination selection and acknowledgment, and appends a superseding immutable profile; the old binding remains retained. Changed/unavailable/foreign-platform/catalog bindings fail closed. To change source or destination, explicitly choose New comparison and save a separate profile; destructive profile edit/delete and automatic schedules are unavailable. Old bindings remain retained, including after catalog root removal. A profile ID is not permission to execute a transfer.

Schema 11 adds the profile table and immutable update/delete guards through the existing catalog actor. Migration keeps an independently openable prior snapshot, preserves catalog/root UUIDs and history, and rolls back on name collisions. Directory identity uses device/object identity plus stable volume token; directory link counts are not object identity. Native fixtures cover reopen, changed default/base/relinked source, reused destination paths, foreign records, profile bounds and migration process exits. Source and destination payloads remain unchanged.
