# Albums / Tags

Owner-requested slice, 2026-11-06. This extends the existing M5/N2 catalog organization; it does not complete the remaining release or original-file recovery gates.

The sidebar opens one searchable album grid in the neutral light/dark interface. Custom and automatic albums appear together, with cached photo covers, counts and a subtle **From tags** label. There are no album-type filters. Album search matches a literal name substring without changing photo filters. Results load in batches of 48; visible covers share the existing bounded preview pipeline. Empty, loading and retry states are explicit.

Opening a tile uses the existing virtualized photo browser, viewer, query, and selection components. **All albums** returns to the grid. Custom albums have **Add photos**, which searches across the catalog and adds up to 500 explicitly selected photos per save. It preserves all existing memberships. Tag albums follow exact tag labels and cannot be manually populated. A photo can appear in several albums. Missing and offline records remain represented; covers are previews, not evidence of an accessible original.

**New album** opens a named, searchable library picker. Empty custom albums are allowed. Creation and initial memberships commit in a single SQLite transaction, with validated stable IDs; invalid or disappeared selections roll back the entire creation. Errors preserve the name and selection. The selection count and save/cancel controls stay in a fixed dialog footer; Close/Escape cannot hide an unresolved save. Existing custom albums reuse version checks and the membership primary key, so adding the same photo again is harmless. The backend enforces name uniqueness after trimming and Unicode lowercase comparison, including archived custom albums and existing tag names. Unicode normalization and exact source-tag comparison remain unchanged. Later source tag observations retain their exact labels, even when they collide with a pre-existing custom name; their distinct origin remains visible.

On Photos, right-click a photo, or focus it and press Shift+F10/the context-menu key. There is no per-photo dots button. **Select** enters selection mode and selects the context photo; the toolbar **Select** enters the same mode without selecting a photo. Photo checkboxes appear on hover or keyboard focus; selection mode reveals photo and day controls. **Done selecting** clears the selection and returns to browsing. **Add to album** offers active custom albums and **Create new album** with that photo preselected. Menus use Chakra v3 keyboard navigation, dismissal and viewport positioning; pickers use the established native modal dialog. Escape/Close returns to the opener. Catalog errors remain visible and retryable. No browser localStorage persistence or external sample image service is used.

## Scanned keywords

The existing read-only metadata worker observes embedded Keywords/Subject. Successful fresh metadata publication and the cached-metadata branch of an explicitly requested scan merge validated source keywords into catalog tags. Existing raw observations stay intact. Existing catalog-removal tombstones take priority, so rescanning cannot resurrect a removed keyword. Import adds observed associations and retains previous associations/history; it does not infer removal from absent metadata. Source files and companion sidecars are never written.

Import is bounded to 64 unique tags per photo, 128 UTF-8 bytes per label and 1 MiB of raw metadata. Invalid or oversized keyword observations are not partially imported; the metadata warning directs the user to Info. macOS retains the pinned ExifTool Keywords/Subject adapter. Windows policy `windows-exif-v3` adds bounded namespace-aware XMP subject bags, JPEG Photoshop IPTC keyword resources (ASCII or declared UTF-8), and EXIF XPKeywords (UTF-16LE). DTDs, unknown entities, oversized packets and unsupported keyword encodings fail explicitly. Standalone sidecar parsing, arbitrary PNG IPTC raw-profile encodings and broad format/native Windows compatibility are not claimed. An authorized rescan refreshes earlier Windows policy rows; no automatic real-library scan runs during development.

## Storage and commands

No catalog schema or identity migration is required. Reuse `catalog_collections`, `catalog_collection_members`, asset tag JSON, raw observations, removal overrides and append-only tag history. Rust-owned IPC adds `CatalogMetadataRequest::Albums { search, offset }` and `CreateAlbum { name, asset_ids }`, with generated `AlbumPage`/`AlbumSummary` types. Requests retain the existing local-main-window permission boundary and database actor. Album projection reads only the catalog. Saved searches and the existing Catalog organizer stay available through **Catalog** on the Albums / Tags header, beside **Saved plans** and **New album**. Browsing a catalog category or saved search opens Photos with that query. Selection-specific album and export tools remain available through the photo selection action.

Code lives in `src/components/AlbumsPage`, `AlbumEditor`, and `PhotoAlbumActions`; recipes/tests are colocated. The scanner integration and atomic creation/projection are in `crates/core/src/library/catalog_metadata/albums.rs`. Windows keyword parsing is in `crates/core/src/media/metadata/keywords.rs`.
