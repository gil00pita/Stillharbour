# M4A validation

M4A is the read-only fixed-source comparison and review gate. This does not accept M4B copying, M4C replacement or M4D backup/restore/protocol operations. The owner requested completing M4A, committing and pushing on 2026-11-01. Platform acceptance remains pending until the exact implementation head completes native CI and its receipts are inspected.

| M4A requirement                   | Implemented evidence                                                                                                                                                                                                                                                                                            |
| --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Fixed source / explicit rebind    | Immutable UUID/native bindings; no changed-base fallback. Rebind review appends a superseding profile with fresh selection and comparison; old profile retained. Core, component and native UI cases.                                                                                                           |
| Read-only complete inventory      | Hidden, unknown, damaged and companion files are inventoried independently of gallery filters. Generated source/destination manifests and neighbor audits; no dataset or probe object is created by compare.                                                                                                    |
| Native containment and conflicts  | Handle-relative no-follow traversal, native root/volume validation and read leases. Existing case/Unicode/type/ancestor conflicts remain distinct and blocked; platform component limits and reserved names are checked conservatively. Future write-specific name publication checks remain M4B.               |
| Quick vs full evidence            | Same-length/restored-time edits remain unverified in Quick; full byte comparison detects content difference. Directory/file revisions and native membership are rechecked. No equality from history or thumbnails.                                                                                              |
| Historical context                | Schema-12 bounded immutable full destination-byte observations; changed-destination category; no Quick/incomplete replacement, automatic history removal, equality reuse or recovery authority. Fresh comparison after reopening.                                                                               |
| Review plan / capabilities        | Typed immutable session descriptor and policy-3 digest. All execution, replacement, fidelity and independent-recovery capabilities remain false. IDs only cross IPC.                                                                                                                                            |
| Review UI                         | Whole-report totals/category-filtered pages, per-side sizes/UTC filesystem dates, full display paths, text-only fallback, companion associations and explicit side-by-side bounded previews. Unsupported images do not disappear.                                                                               |
| Contextual failure / invalidation | Changed file/directory, unavailable listing, namespace occupant, bounded inventory, overlap, stale identities, unsupported objects, cancellation, revoked root and incompatible writer lease fixtures. Incomplete/failed/canceled runs have no executable plan or trusted digest; previous history is retained. |
| Bounded resource use              | One comparison and one preview, no unbounded queue; inventory/name/depth/page/issue/input/output/history bounds. All owned comparison, digest and preview source reads use shared PacedIo. Decoder/metadata/physical-I/O limitations remain explicit.                                                           |
| Preservation gates                | No copy/replacement/adoption/restore/approval command is introduced. Original mutation and recovery guards remain unchanged; production instrumentation exclusions are checked.                                                                                                                                 |

Current checks and exact commands/results are recorded in IMPLEMENTATION_LOG.md. The Windows native receipt includes source preview, filtered review, a reopened prior observation, reviewed superseding profile, fresh comparison IDs and unchanged source/destination audits. The macOS source fixture intentionally contains a link loop: its UI must report incomplete with a blocked unsupported loop, no trusted digest/review plan or saved history, and uncertain remaining rows. Preview and rebind remain read-only, while clean-root native core/integration cases validate full historical context on macOS. Native decoder integration additionally renders both sides, rejects stale/foreign/unsupported inputs and verifies retained bytes. The migration matrix includes schema 11 at all three existing process-exit boundaries (30 exits across v2–11), retained snapshots and transaction collision rollback.

Residual limits are part of the M4A contract: comparison is not an atomic snapshot; external OS calls can block; OS access-time changes are not application metadata edits; byte equality does not establish metadata/stream fidelity or independent-device recovery. Companion associations are bounded naming context, not an assertion that every possible proprietary bundle relation is understood. No direct remote protocol, physical-I/O ceiling, playable MP4, prospective write-name capability or real-library mutation is advertised by M4A.
